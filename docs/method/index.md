# Method

Ariad is an operating system for human-agent software work.

It is not a prompt collection. It is not a documentation template by itself. It is a method that tells an agent how to participate in a project without dissolving the project's memory, standards, and product intention.

The method has six core pieces:

- explicit human-agent roles,
- a triad for keeping process, project, and product connected,
- a story lifecycle for bounded delivery,
- mandatory checkpoints that prevent silent drift,
- living documentation that lets the repository remember itself,
- a separation between Ariad's method contract, project contract, and configurable Navigator preferences.

Ariad is opinionated. It ships with [Navigator preference defaults](contracts-and-preferences.md), such as conservative commit and push behavior, full checkpoints for non-trivial work, and documentation updates when project truth changes. These defaults are recommended starting points, not universal laws. Advanced Navigators and projects can override them explicitly.

Ariad's strongest [methodological roots](methodological-roots.md) are Extreme Programming and Kanban. It borrows small verified change, feedback, refactoring, visible work, explicit policies, and limits against uncontrolled scope expansion, then adapts them to human-agent collaboration.
